The Neuro-Symbolic Architecture at a Glance

This project implements a dual-lane log triage engine combining classical automata theory with neural generative reasoning. The symbolic fast path leverages a 6-state Minimal Deterministic Finite Automaton (DFA) running in C++14 to parse and validate log structure in linear time, accompanied by a 4-state Moore Machine session monitor that detects behavioral brute-force patterns across structurally compliant entries.

Events that trigger DFA rejection (structural anomaly) or Moore flags (behavioral abuse) are escalated to an asynchronous, bounded-queue neural slow path. Prior to API egress, a formal 7-tuple Single-Tape Turing Machine acts as a payload transducer, physically scrubbing sensitive credentials and PII on its tape to ensure strict regulatory compliance (GDPR/DPDP).

The Enterprise Log Crisis

Data Deluge and the Downstream Cognitive Chokepoint

In modern cloud enterprise networks, security and infrastructure daemons produce massive volumes of semi-structured text. A medium-scale banking or e-commerce infrastructure routinely generates in excess of 100,000 log events per second.

Catastrophic Latency: 1.5s / event • Bankrupting Cost: $0.002 / call ($17M/day) • Rate Limits: HTTP 429 System Blindness • Privacy Breach: Raw PII leaked to Cloud SYSTEM CRASHES UNDER REAL-WORLD LOAD

The False Economy of "Dumb" Pipelines

Historically, organizations attempted to filter events using static regex strings in syslog daemons. However, regex engines that rely on Non-Deterministic Finite Automata (NFA) with backtracking suffer from Regular Expression Denial of Service (ReDoS). A maliciously crafted input forces exponential time complexity 𝒪(2N), causing CPUs to peg at 100% utilization.

Furthermore, pure regex rules cannot detect multi-step behavioral anomalies (such as a slow password-guessing attack across three valid attempts) and cannot explain novel or zero-day attack payloads.

The Need for Formal Language Theory

By formally classifying normal system telemetry as a Regular Language, we construct deterministic finite-state recognizers that guarantee linear time execution 𝒪(N) with mathematical certitude. The core problem of modern telemetry is not detection—it is rapid, zero-cost routing.

Our architecture routes 95% of routine entries directly to local storage at zero cost, reserving expensive AI inference exclusively for events that deviate from the formal language grammar.

Theoretical Foundations

Formal Language Classification Across the Chomsky Hierarchy

The Chomsky Hierarchy categorizes formal grammars into four nested classes based on generative power. Selecting the correct automaton class is fundamental to building an optimal, non-backtracking triage engine.

Mathematical Formulation of Log Grammar

Let Σ denote the formal alphabet of abstract token classes:
Σ = { LEVEL, IP, USER, STATUS, OTHER }

A healthy login event string w ∈ Σ* belongs to the regular language Lbaseline if and only if it strictly follows the production rule:
S → LEVEL · IP · USER · STATUS

Because Lbaseline is a regular language, it satisfies the Myhill-Nerode equivalence relation with a finite index of exactly 6 equivalence classes.

The Boundary of Computation

While linear structures belong to Type 3, complex injection payloads (such as nested JSON queries or recursive SQL injections with matched parentheses ((1))) belong to Type 2 (Context-Free) or Type 0 (Unrestricted).

By designing a DFA to recognize normal Type 3 behavior, any syntax deviation (such as injected symbols or invalid token counts) immediately drives the automaton into an irreversible Trap State (qE), signaling a structural anomaly.

System Architecture

High-Level Blueprint: Symbolic Fast Path vs. Neural Slow Path

The Hybrid Anomaly Engine is engineered as a two-lane architecture. The Symbolic Fast Path runs locally on bare metal in C++, while the Neural Slow Path operates asynchronously via a rate-limited JSON escalation channel.

Symbolic Fast Path Responsibilities

• Microsecond Execution: Native C++ compilation ensures deterministic execution overhead of under 200 microseconds per event.
• ReDoS Resistance: Unlike backtracking regex engines, the total transition table never branches backwards.

Neural Slow Path Safeguards

• Bounded Memory Queue: Protects local hosts from memory exhaustion during large DDoS spikes.
• Pre-Egress Turing Redaction: Ensures that unencrypted user credentials never escape the private host perimeter.

The Symbolic Fast Path: Lexer

Character-Level Regular Expressions and Abstract Token Mapping

The Lexer decomposes raw ASCII telemetry into discrete lexemes and classifies each into a formal token class over alphabet Σ = { LEVEL, IP, USER, STATUS, OTHER }.

Token Class Formal Character-Level Regular Expression Matching Lexeme Sample Lexer Semantic Role
LEVEL \[INFO\] [INFO] Establishes logging severity class boundary
IP o\.o\.o\.o where o = 25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9] 192.168.1.50 Validates IPv4 octet bounds (0–255)
USER User_[A-Za-z0-9]+ User_Admin Verifies corporate identity naming conventions
STATUS Success | Failed Success Binary authentication outcome indicator
OTHER .* (any lexeme failing above patterns) DROP_TABLE Catches malformed strings, SQL keywords, flags

Lexical Analysis Mechanics

The C++ lexer splits incoming strings at whitespace boundaries. Each whitespace-delimited lexeme is tested in priority sequence against POSIX Extended Regular Expressions compiled ahead-of-time.

Notice that IP address validation is not merely a naive digit check; it enforces mathematical bounding [0, 255] for each octet. An input such as 999.1.1.1 is automatically rejected and classified as OTHER, immediately exposing spoofed payloads.

Token Stream Generation

Consider an attack event: [INFO] 192.168.1.50 DROP_TABLE User Success.

[INFO] ──► Token: LEVEL 192.168.1.50 ──► Token: IP DROP_TABLE ──► Token: OTHER [ANOMALY DETECTED] User ──► Token: OTHER (Missing User_ prefix) Success ──► Token: STATUS

The resulting token array ⟨ LEVEL, IP, OTHER, OTHER, STATUS ⟩ is transferred directly to the DFA input buffer.

The Minimal Baseline DFA

Mathematical 5-Tuple Formulation and State Dynamics

The baseline structure recognizer is formally defined as a Deterministic Finite Automaton (DFA) 5-tuple:
M = (Q, Σ, δ, q₀, F)

Formal 5-Tuple Specification

• State Set Q: { q₀, q₁, q₂, q₃, q₄, qE }
• Alphabet Σ: { LEVEL, IP, USER, STATUS, OTHER }
• Start State q₀: The initial state prior to consuming tokens.
• Final / Accept State F: { q₄ } (Double Circle).
• Trap / Dead State qE: An absorbing state representing rejection.

Semantic State Interpretation

• q₁: Successfully parsed and validated LEVEL token.
• q₂: Successfully parsed and validated IP token.
• q₃: Successfully parsed and validated USER token.
• q₄: Successfully parsed STATUS (Grammar satisfied).
• qE: Irreversible trap state entered on unexpected token.

Total Transition Function

Full State Matrix Definition (Table 3) and Minimality Proof

To guarantee deterministic execution, the transition function δ: Q × Σ → Q is mathematically total across all |Q| × |Σ| = 6 × 5 = 30 state-token combinations.

State q ∈ Q LEVEL IP USER STATUS OTHER Acceptance Status
→ q₀ (Start) q₁ qE qE qE qE Non-final
q₁ qE q₂ qE qE qE Non-final
q₂ qE qE q₃ qE qE Non-final
q₃ qE qE qE q₄ qE Non-final
q₄ (Final) qE qE qE qE qE ACCEPT (Double Circle)
qE (Trap) qE qE qE qE qE REJECT (Absorbing)

Proof of Minimality (Myhill-Nerode Equivalence Theorem)

Theorem: The baseline automaton M has the minimum possible number of states for regular language Lbaseline.

Proof: Under the Myhill-Nerode theorem, two states p, q are equivalent (p ≡ q) iff for all strings z ∈ Σ*, δ̂(p, z) ∈ F ⇔ δ̂(q, z) ∈ F. Consider distinguishing suffixes z:

• Suffix z = ε distinguishes q₄ (since q₄ ∈ F) from all {q₀, q₁, q₂, q₃, qE} (since none ∈ F).
• Suffix z = STATUS distinguishes q₃ (leading to q₄ ∈ F) from {q₀, q₁, q₂, qE} (all leading to qE ∉ F).
• Suffix z = USER · STATUS distinguishes q₂ from {q₀, q₁, qE}.
• Suffix z = IP · USER · STATUS distinguishes q₁ from {q₀, qE}.
• Suffix z = LEVEL · IP · USER · STATUS distinguishes q₀ from qE.

Every pair of states (p, q) in Q is pairwise distinguishable. Therefore, no two states can be merged, and the automaton of Table 3 is already mathematically minimal with |Q| = 6. ∎

Behavioral Session Monitor

Finite State Transducer for Stateful Brute-Force Detection

A structurally valid log is not necessarily benign. A password-spraying bot or distributed credential stuffing attack can send thousands of perfectly formed authentication requests. The Moore Machine acts as a stateful behavioral monitor.

Mathematical Transducer Definition

A Moore Machine is a 6-tuple MMoore = (S, S₀, Σsession, Λ, T, G) where:
• State Set S: { m₀, m₁, m₂, m₃ }
• Initial State S₀: m₀ (0 consecutive failures)
• Input Alphabet Σsession: { Success, Failed }
• Output Alphabet Λ: { OK, FLAG }
• Output Function G: G(m₀) = G(m₁) = G(m₂) = OK, and G(m₃) = FLAG

Per-Source IP Session Table

The engine maintains an internal hash map:
std::unordered_map<std::string, MooreState> ipStates_;
Whenever a log line receives an ACCEPT verdict from the baseline DFA, its extracted IP address and authentication status (Success vs Failed) are passed to the Moore transducer.

Behavioral Edge Case Handling

The Moore machine maintains state across discrete HTTP or socket events. If an attacker alternates attempts across 2 failures and 1 success, the state counter continuously resets to m₀, preventing false alarms on legitimately forgotten passwords. Only persistent, consecutive authentication failures from a single IP reach m₃ and trigger escalation.

Data Privacy & The Turing Machine

A Formal 7-Tuple Memory Tape Transducer for Pre-Egress PII Redaction

When anomalous logs are escalated to cloud-hosted LLM endpoints, raw text may contain confidential API tokens, bearer keys, and user passwords. To comply with GDPR, HIPAA, and DPDP mandates, we deploy a Single-Tape Turing Machine as a payload sanitizer.

Mathematical 7-Tuple Definition

The Sanitizer is formulated as:
MTM = (Q, Σ, Γ, δ, q₀, B, F)
• Q: { qscan, qmatch, qmask, qhalt }
• Σ: Printable ASCII input characters.
• Γ: Tape alphabet Σ ∪ { B, 'X' } (B is blank symbol).
• q₀: Start state qscan.
• F: Halting state { qhalt }.

Transition Function δ Logic

1. Scanning Mode (qscan): Head reads symbols moving Right (R). If symbol is B, enters qhalt.
2. Pattern Detection (qmatch): Identifies secret triggers (pass=, token=, pwd=).
3. Masking Mode (qmask): Overwrites sensitive characters with mask symbol 'X' on the tape until hitting a whitespace or delimiter.

Empirical Tape Execution Metrics

In benchmark tests across 16 sample events, the Turing Machine executed a total of 153 tape steps, masking 41 sensitive characters across passwords and GitHub personal access tokens (token=ghp_...) with zero memory faults.

The Neural Slow Path

Bounded Memory Queueing and Schema-Validated LLM Forensic Analysis

The neural slow path handles the small fraction of events (typically 1–5%) that fail symbolic verification. To safeguard cloud credentials and prevent host memory crashes, escalation is buffered by a memory-bounded queue.

Bounded Queue & Rate Limiter

• Bounded Capacity (K = 1,000 events): Drops or aggregates events when the queue reaches saturation, preserving system stability during sudden DDoS surges.
• Rate Throttling: Enforces an API dispatch frequency (e.g., 15 RPM) that completely prevents cloud providers from issuing HTTP 429 Too Many Requests blocks.
• Retry & Timeout: Failed network calls trigger exponential backoff before analyst notification.

Structured Forensic Prompt Schema

The C++ engine serializes the event into a strict JSON payload:

{ "event_type": "ssh_login", "sanitized_log": "[INFO] 192.168.1.75 pass=XXXX Failed", "dfa_result": "REJECT", "visited_states": ["q0", "q1", "q2", "q3", "qE"], "last_valid_state": "q3", "reason": "unexpected token at position 4" }

Decidability & Rice's Theorem

Theoretical Limits of Automata and Justification for Neuro-Symbolic Triage

A common question in computer science is: "Why can't we simply build a larger DFA or Turing Machine that recognizes all malicious attacks without using an LLM?" The answer is grounded in foundational computability theory.

Formal Statement of Rice's Theorem

Rice's Theorem (1953): Any non-trivial semantic property of a language recognized by a Turing Machine is undecidable. Formally, let 𝓒 be a set of partial computable functions. If 𝓒 ≠ ∅ and 𝓒 ≠ 𝓕 (the set of all partial computable functions), then the language problem:
L𝓒 = { ⟨M⟩ | L(M) ∈ 𝓒 }
is mathematically undecidable.

Application to Threat Detection

Whether an arbitrary program or script is "malicious" is a non-trivial semantic property of its behavior. Therefore, no algorithm, DFA, or Turing Machine can decide for every arbitrary program whether it is malicious.

This mathematical reality dictates our architectural division of labor:
• The DFA models only "normal" structure (which is decidable).
• The LLM operates as a probabilistic heuristic, providing contextual evidence rather than an impossible decision procedure.

The Role of Redaction Transducers

While semantic classification of attacks is undecidable, syntactic string transformation (such as PII masking) is computable and belongs to the class of functions computed by Turing Transducers.

By limiting our Turing Machine strictly to data sanitization f: Σ* → Γ*, we preserve formal termination guarantees while delegating ambiguous reasoning to the neural layer.

Threat Model & Hardening

Adversarial Robustness and Defense-in-Depth Protections

Like any cyber defense mechanism, the hybrid anomaly engine itself is a target for intelligent adversaries attempting evasion, timing side-channel exploitation, or denial of service.

Adversarial Attack Vectors

• Token Smuggling: Inserting whitespace or null bytes to split tokens across lexeme boundaries.
• DDoS on Slow Path: Flood of malformed lines intended to exhaust LLM API budgets and saturate queues.
• Slow Brute-Force: Spreading password guesses across multiple IP subnets to evade the 3-failure Moore threshold.

Engine Countermeasures

• Strict Canonicalization: The lexer strips control characters prior to regex compilation.
• Bounded Queue Drop: Excess anomalies beyond queue capacity trigger local logging without blocking engine threads.
• Global Sliding Window: Augments per-IP tracking with global subnet rate limiting.
